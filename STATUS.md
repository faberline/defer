# Defer status

## Scope

This document describes the support contract in the current repository source.
It does not claim that every listed gate ran in this working session. A release
can contain an older contract.

The rows are the Google Cloud Tasks feature checklist plus the operational
surfaces defer owns. Use the [README](README.md) for the product workflow and
capabilities. Use the [roadmap](ROADMAP.md) for future outcomes and explicit
non-goals.

## State definitions

| State | Meaning |
|---|---|
| Supported | The current source has a public contract, an implementation, and a named executable gate for the stated scope. |
| Limited | The current source supports the stated scope, but the Limits cell names a material boundary. |
| Not supported | The behavior is not part of the current product contract. The Evidence cell points to a future outcome or a non-goal. |

| Scheduled ETA | `scheduled-eta` | Supported | Every task carries `schedule_at`. A task is eligible only once it is due; among due tasks the higher `priority` (u8, default 10) leases first, and equal priority leases in creation order. | ETA resolution is the dispatch tick (`--dispatch-tick-ms`, default 100 ms). A past `schedule_at` is due immediately. | `cargo test -p defer --test it -- task_lifecycle::` |
| HTTP target dispatch | `http-target-dispatch` | Supported | A due task is delivered to its `target.url` as one HTTP request whose body is the task `payload` as JSON, after the lease is committed and never before. | One process sends at most `--dispatch-concurrency` (default 32) target requests at a time; the queue's committed permits stay global across replicas. | `cargo test -p defer --test it -- http_dispatch::` |
| Target method and headers | `target-method-and-headers` | Supported | `target.method` (default `POST`) and `target.headers` are sent verbatim on every attempt, alongside the defer attempt headers. | An unparseable method commits a nack instead of a transport attempt. | `cargo test -p defer --test it -- http_dispatch::` |
| Completion on 2xx | `completion-on-2xx` | Supported | Any 2xx answer commits the attempt as acked and the task as `Succeeded`; every other status and every transport error commits a nack. | A 3xx is a failure, not a follow. | `cargo test -p defer --test it -- http_dispatch::` |
| At-least-once retry | `at-least-once-retry` | Supported | A nacked or expired attempt reschedules the task. | Retry policy | `retry-policy` | Limited | A task's `max_attempts` (default 3) bounds delivery. The queue's `retry_backoff_ms` doubles per failed attempt, capped at 2^16 times the base. | Queue rate, burst, and in-flight limits | `queue-rate-and-concurrency` | Supported | `PUT /v1/queues/{queue}` sets `max_in_flight`, `max_dispatch_per_tick`, `max_dispatches_per_second`, `max_burst_size`, `lease_ttl_ms`, and `retry_backoff_ms`. | Pause, resume, and disable | `queue-pause-resume-disable` | Supported | `POST /v1/queues/{queue}/control` sets `Running`, `Paused`, or `Disabled`. | Task create and batch create | `task-create-and-batch` | Supported | `POST .../tasks` creates one task and `POST .../tasks:batch` creates a batch atomically. A refusal answers the shared error envelope: 404 `not_found` for a missing queue, 409 `conflict` for a duplicate id, and 409 `queue_disabled` for a disabled queue. | A commit failure that is not a scheduler refusal answers 500 `internal` without the underlying error text. | `cargo test -p defer --test it -- http_api:: rate_limits::` and `cargo test -p defer-queue --lib` |
| Task inspection and cancel | `task-status-and-cancel` | Limited | `GET .../tasks/{task_id}` returns the task state (`Scheduled`, `Leased` with executor and epoch, `Succeeded`, `DeadLettered`, `Canceled`). `DELETE` cancels a scheduled or leased task; a leased task's in-flight attempt can no longer ack. | Target signing | `target-signing` | Supported | With `--target-signing-key-id` and `--target-signing-secret-file` (secret of at least 32 bytes) every target request carries `x-defer-timestamp-ms`, `x-defer-key-id`, and `x-defer-signature: v1=<base64 HMAC-SHA256>` over the length-delimited idempotency key, attempt id, target URL, timestamp, and exact body bytes. | One active key per process; rotation is a restart with the new id. | OIDC and OAuth target tokens | `oidc-oauth-target-tokens` | Not supported | None. | Defer mints no Google identity tokens for a target. | [Cloud identity target tokens](ROADMAP.md#cloud-identity-target-tokens) |

## Evidence policy

A `Supported` or `Limited` row names at least one command that exists in this
repository. `cargo test -p defer --test it -- <file>::` selects one file in
`crates/defer/tests/it/`, and `--test operator` is `crates/defer/tests/operator.rs`;
`bash scripts/<name>.sh` scripts live in `scripts/`.
A `Not supported` row names no command; it links the roadmap outcome or
non-goal that owns the gap.

Historical acceptance runs, benchmark notes, and retired design documents do
not define the current contract. When a gate and this table disagree, the
gate is right and this table is stale.
